# 文章组件契约

先按[组件选用与布局规范](editorial-guidelines.md)判断哪些内容需要什么组件，再用本契约生成 Markdown 并调用 render-article.mjs；无需手写 HTML、配色或 CSS。以下组件随所选模板排版，代码窗口保留统一的苹果圆点结构与高亮，外框可随风格调整，配图外观独立选择。

## 覆盖范围

当前覆盖日常公众号文章常用的 35 类组件。基础文字、强调、引用、提示、操作、信息展示、代码与图片都有对应写法。它们用于发布静态内容；交互表单、视频播放器、数学公式和数据驱动图表不属于本渲染器的专用组件。需要图表时可插入已生成的图表图片，需要复杂排版时先明确具体内容，不把“常用组件齐全”理解为任意 HTML 都可运行。

| 信息类型 | 已支持的展示方式 |
| --- | --- |
| 文字与结构 | 文章标题、章节、小标题、正文、开篇引言、分隔线 |
| 局部强调 | 加粗、斜体、高亮、下划线、删除线、行内代码 |
| 引用与结论 | 普通引用、署名引用、首尾成对的金句引文、核心结论 |
| 提醒与回顾 | 补充说明、实用提示、注意事项、完成核对、摘要 |
| 顺序与进度 | 无序列表、有序列表、检查清单、操作步骤、时间线 |
| 信息与比较 | 对比表格、信息卡、术语解释、关键数据、常见问答 |
| 技术与媒体 | 高亮代码／终端窗口、原图、圆角阴影图、苹果窗口图、图注 |
| 资料来源 | 来源与延伸阅读、文字链接 |

## 完整清单

| 组件 | 输入写法 | 使用场景 | 输出角色 |
| --- | --- | --- | --- |
| 独立文章标题 | 文件开头的 `# 标题` | 公众号标题栏，单独复制 | articleTitle，正文之外 |
| 章节标题 | `## 标题` | 大段落结构，自动编号 | section、h2、sectionNumber |
| 小标题 | `### 标题`，也支持四至六级 | 章节内的主题 | subhead、h3 |
| 正文段落 | 段落之间空一行 | 普通叙述 | paragraph |
| 开篇引言 | `:::lead` 容器 | 导语、读者问题 | lead、leadParagraph |
| 加粗重点 | `**重点**` | 结论、关键操作 | strong |
| 斜体 | `*文字*` | 语气、作品名称 | em |
| 高亮 | `==文字==` | 少量重点标记 | highlight |
| 下划线 | `++文字++` | 需要关注的细节 | underline |
| 删除线 | `~~文字~~` | 作废的表述 | del |
| 行内代码 | 反引号包围短命令、文件名 | 文字中的短代码 | inlineCode |
| 普通引用 | `> 引用文字` | 引用他人内容 | quote |
| 带署名引用 | `:::quote 来源或作者` | 引文及明确来源 | quote、quoteCredit |
| 金句引文 | `:::pullquote`，可写署名 | 重要引文，首尾成对引号 | pullquote、quoteMark、quoteMarkEnd、takeawayParagraph |
| 核心结论 | `:::takeaway` | 一句可执行的结论，不加引号 | pullquote、takeawayParagraph |
| 补充说明 | `:::note 可选标题` | 非关键的补充信息 | note、componentLabel |
| 实用提示 | `:::tip 可选标题` | 技巧、快捷方法 | tip、componentLabel |
| 注意事项 | `:::warning 可选标题` | 实际需要注意的问题 | warning、warningLabel |
| 完成核对 | `:::success 可选标题` | 如何确认操作成功 | success、successLabel |
| 摘要／回顾 | `:::summary 可选标题` | 若干要点、本节回顾 | summary、componentLabel |
| 无序列表 | `- 内容` | 并列信息，可嵌套 | list、listItem |
| 有序列表 | `1. 内容` | 普通顺序，可指定起始序号 | list、listItem |
| 检查清单 | `- [ ] 内容` 或 `- [x] 内容` | 待核对与已完成项目 | list、listItem，静态勾选符号 |
| 操作步骤 | `:::steps` 内放有序列表 | 带编号的步骤与说明 | steps、stepRow、stepBadge、stepBody |
| 代码／终端窗口 | 带语言的 fenced code | 代码、命令、配置、纯文本口令 | codeBlock、codeHeader、codePre、codeText、syntax* |
| 对比表格 | Markdown 表格 | 简短、多列对比 | tableWrap、table、th、td |
| 信息卡 | `:::card 标题` | 案例、术语、补充资料 | card、componentLabel |
| 术语解释 | `:::definition 可选标题` | 定义、概念、名词释义 | definition、componentLabel |
| 关键数据 | `:::facts 可选标题` 内放数据列表 | 数值、短结论与说明 | facts、factRow、factValue、factLabel |
| 常见问答 | `:::faq 可选标题` 内放问答列表 | 读者常见问题 | faq、faqRow、faqQuestion、faqAnswer |
| 时间线 | `:::timeline 可选标题` 内放阶段列表 | 时间、过程、里程碑 | timeline、timelineRow、timelineDot、timelineBody |
| 图片与图注 | Markdown 图片；`:::image 外观` 可单独指定 | 原图、圆角阴影、苹果窗口 | imageBlock、imageFrame*、imageWindow*、image、caption |
| 分隔线 | 独立一行 `---` | 内容转折 | hr |
| 来源与延伸阅读 | `:::source 可选标题` | 链接、来源、文末说明 | source、sourceParagraph |
| 文字链接 | `[名称](https://example.com)` | 阅读来源、访问工具 | link |

星号强调已适配中文边界：`**“引文”**：`、`*“快”*` 这类紧贴中文标点、前后没有空格的加粗与斜体可正常解析，不必为了加粗在中文里补空格。下划线强调与三星组合仍按 CommonMark 原规则处理；`a**"b"**c` 这类拉丁字母紧邻标点的写法保持字面星号。

## 表格

表格使用普通 Markdown 语法，按内容分配列宽，短数值与名称保持完整。列较多时可在表格内左右滑动；长篇介绍放在正文，表格只保留用于比较的要点。用 `:---`、`:---:`、`---:` 分别指定左、中、右对齐，数值列适合右对齐。

## 容器写法

开始行独立，以 `:::类型 可选标题` 开头，以独立的 `:::` 结束。类型用清单中的小写英文。内部支持 Markdown、列表、图片、代码及嵌套容器；每层各有一个结束标记。不要把章节标题塞进提示框，用短标题或加粗即可。

~~~markdown
:::lead
先写读者正在遇到的问题，再说明文章能提供什么帮助。
:::

:::quote 来源或作者
这里放实际需要引用的文字，不编造引文和作者。
:::

:::tip 保存一个常用输入
下次替换内容，就能少做几次重复操作。
:::

:::warning 保存前核对文件名
确认目标位置和文件名，再保存最终结果。
:::

:::success 怎样确认完成
结果可以正常打开，关键内容准确，保存位置能够找到。
:::

:::summary 要点回顾
- 准备材料。
- 先用小样本确认效果。
- 核对结果后再保存。
:::
~~~

note、tip、warning、success、summary、source、definition、facts、faq 不写标题时使用语义默认标题。lead、steps、card、takeaway、timeline 默认不额外插入标题；quote 和 pullquote 的可选标题表示署名或来源，放在引用后面。image 容器的参数表示外观与窗口名，详见配图章节。

pullquote 自动将开引号“放在左上角、闭引号”放在右下角，沿容器内边距对齐，两者大小与颜色一致；署名位于闭引号之后。无需手动补装饰引号，模板切换与复制正文时会保留完整的一对及其左右对齐样式。

也接受常见的提示引用写法：

~~~markdown
> [!NOTE]
> 补充说明。

> [!TIP]
> 实用提示。

> [!WARNING]
> 注意事项。
~~~

`[!IMPORTANT]` 映射到摘要框，`[!CAUTION]` 映射到注意事项框。需要自定义标题时使用容器。

## 步骤与检查清单

~~~markdown
:::steps
1. **准备内容**

   整理资料，确保材料完整。
2. **选择对应功能**

   按提示提交内容，先查看一个小样本。
3. **核对结果**

   检查关键细节，再保存。
:::

- [x] 标题清楚。
- [ ] 配图检查完成。
~~~

步骤内补充段落缩进三个空格，并留空行。渲染后保留正确起始序号。清单是用于发布的静态符号，不是交互表单。

## 代码与终端

三个反引号或波浪号围起代码，开头写语言。支持 `title=文件名`；名称含空格时用引号。不要手工加入圆点、行号、HTML span 或颜色。

~~~markdown
```javascript title=example.js
// 代码文字和换行保持原样
const name = "Hello";
console.log(name);
```

```python
def greet(name):
    return f"Hello, {name}"
```

```bash
# 终端命令
echo "Hello"
```

```text
准备内容 → 选择功能 → 核对结果 → 保存
```
~~~

- 统一为深色苹果窗口：左上角红黄绿圆点，右上角语言或文件名，正文等宽字体。
- 已打包语言：javascript、typescript、python、bash、shell、powershell、xml、css、sql、yaml、json、ini、diff、go、java、cpp、csharp、rust、dockerfile、markdown。支持库原生别名，如 js、ts、py、sh、html、yml、md。
- bash/sh 用于命令脚本；shell 用于带提示符的终端记录；text/plaintext 用于操作口令和非代码文字。
- 不标语言时使用纯文本。未收录语言保留原文并报告回退，不猜测语言。需要高亮时明确标注正确语言。
- 关键字、字符串、数字、注释等由 highlight.js 解析。每个 span 都有行内颜色，不依赖 CDN 或公众号加载 CSS。
- 长行可视觉折行，实际代码内容不改写。空格缩进显示更稳定；窗口样式不代表命令可执行或已执行。

## 数据、问答、定义与时间线

~~~markdown
:::facts 示例数据
- **20 分钟**：用于演示时间信息的展示方式。
- **3 步**：完整操作流程。
:::

:::definition 什么是输入模板
**输入模板**是可以重复使用的输入结构，保留共同要求，下次只替换内容。
:::

:::faq 常见问题
- 可以先处理一小部分吗？

  可以，先用小样本确认效果。
- 结果需要核对吗？

  需要，对照原始材料检查。
:::

:::timeline 处理过程
- **准备阶段**

  整理材料，说明期待的结果。
- **完成阶段**

  核对结果，保存到指定位置。
:::
~~~

facts 每项写成 `- **数值或短结论**：说明`，一项一段。突出值使用加粗，说明写在冒号后；不凭空补实测数据或数量。需要多列比较时使用表格。

faq 每项第一行是问题，空行后缩进两个空格写回答。每个问题独立展示，回答可以继续写段落或列表。只写问题不写回答时不会补造答案。

timeline 使用列表，每项第一段写日期或阶段，后续段落缩进两个空格。采用连线节点展示，不依靠网页脚本表现进度。

## 配图外观选择

| 外观 | ID | 效果 |
| --- | --- | --- |
| 原图 | plain | 直接展示图片，保留原有比例 |
| 圆角阴影 | rounded-shadow | 12px 圆角、细边框与轻柔阴影 |
| 苹果窗口 | mac-window | 浅色窗口顶栏、左上角红黄绿圆点、可选窗口名、圆角与阴影 |

整篇的默认外观通过 `--image-style "圆角阴影"` 或 `--image-style mac-window` 指定；未指定时为原图。HTML 右侧操作面板中的「配图外观」可随时切换，它独立于文章模板，只影响未单独指定外观的段落配图。

~~~markdown
![跟随整篇设置的配图](./images/overview.jpg "图注")

:::image rounded-shadow
![结果插图](./images/result.jpg "圆角阴影图注")
:::

:::image mac-window 工具操作画面
![软件截图](./images/screenshot.jpg "苹果窗口图注")
:::

:::image plain
![需要直接展示的原图](./images/detail.jpg "原图图注")
:::
~~~

每个 image 容器只放一张独立 Markdown 图片。外观参数支持 ID 或中文名；苹果窗口后可追加窗口名，不填则使用图片替代文字。图注仍来自图片的双引号 title，放在窗口外，避免和窗口名混淆。空参数的 `:::image` 跟随默认外观。

单张指定优先于整篇默认。切换文章模板不覆盖配图选择；复制正文时保留外框、顶栏、圆点及行内阴影。外观通过 HTML 组件展示，不修改源图片像素或封面比例。素材下载入口保存原图，图注和装饰由正文 HTML 提供；公众号粘贴后的结果仍需在实际编辑器预览确认。

## 图片、表格和来源

~~~markdown
![图片替代文字](./images/step.jpg "图：完成后检查这里")

| 场景 | 检查内容 |
| :--- | :--- |
| 整理文字 | 姓名、日期 |
| 处理图片 | 尺寸、文字 |

:::source 来源与延伸阅读
[资料名称](https://example.com/article)。
:::
~~~

图片单独放一段才生成完整配图组件，行内图片不套窗口。图注来自双引号 title，替代文字与图注分别填写。本地路径相对 Markdown 文件解析。表格尽量为两至三列、短句；支持左／中／右对齐。

## LLM 的使用方式

组件决策与组合规则统一维护在[组件选用与布局规范](editorial-guidelines.md)，包括内容对应表、易混淆组件、文章类型的布局参考、强调与卡片密度、配图位置、正反例和自检。写作或排版前读取该规范；本文件负责准确语法，不要求清单中的组件全部出现。

组件全览示例：assets/demo-article.md，按内容类别展示 35 类组件及常用变体，包括普通与署名引用、默认与自定义提示标题、五种提示引用、三级至六级标题、列表续号与嵌套、表格对齐、全部代码高亮颜色角色，以及默认、原图、圆角阴影、苹果窗口和行内图片。它仅用于查看与验证组件，不作为日常文章大纲；配图示例集中在该文件的配图章节，使用 assets/demo-illustration.jpg。实现：scripts/article-components.mjs、highlight-code.mjs、assets/image-appearance.mjs 和 assets/theme-engine.mjs。本地开发回归测试会核对全部注册组件的文档、写法变体与所有模板的正文样式角色；扩展时同步更新契约与示例。
