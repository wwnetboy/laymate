用户可指定中文名、ID 或已有别名，例如：

- 使用 $laymate，按「网格宣言」排版这篇观点文章。
- 使用 $laymate，套用「旅途票根」，保留原文。

配置位于 `assets/templates/<id>.json`，渲染脚本和 HTML 选择器自动读取目录，无须维护另一份固定名单。`assets/previews/` 每款保留一张概览图，便于选风格，不参与文章渲染。

风格全览使用 `assets/gallery-samples.json` 中的独立主题文章：旅行模板展示旅途记录，终端模板展示命令操作，菜单模板展示食谱，其他模板按各自适用场景安排标题、引言、至少两个章节、正文与组件。页面最大宽度为 1680px 并居中，桌面三列、每屏一行，窄屏调整为两列或一列；卡片中可滚动，完整组件在当前页弹窗展示。顶部可按明暗、主色和风格组合筛选，支持叠加搜索、一键清除条件与无结果提示。明暗按实际文章纸张背景判断；色系和风格在 `assets/gallery-filters.json` 中维护，多色或多风格模板可同时归入多个分类。可生成自包含的可搜索全览页：

~~~text
node "<skill-dir>/scripts/render-template-gallery.mjs" --output "<示例目录>/风格模板全览.html" --article "<示例目录>/组件样式全览.html"
~~~

`--article` 可选，提供时将该文件内嵌为完整组件弹窗的内容；未提供时使用 `assets/demo-article.md` 生成组件全览。外部卡片主题文章与弹窗内容独立。全览页使用真实行内排版的文章预览，无需外部图片、字体或网络服务。维护本源码项目时保存在根目录 `examples/`；日常文章仍使用自己的日期归档目录。需要用同一篇内容比较排版时，渲染用户提供的文章并切换模板。

只展示部分模板时，可加 `--templates "apricot-bulletin,blue-green-guide"`，用逗号分隔 ID；卡片按模板目录顺序显示。这类临时对照输出到系统临时目录，项目的 `examples/` 统一只保留 `风格模板全览.html` 和 `组件样式全览.html`，八款截图风格也在完整风格全览中查看。

查看全部组件时渲染 `assets/demo-article.md` 并切换模板；它是组件全览，不是文章大纲。检查桌面与手机上的实际效果；源码维护者可使用项目根目录本地 `dev/` 中的浏览器检查工具，它不随 Skill 安装。先按[组件选用与布局规范](editorial-guidelines.md)确定内容安排，再按[文章组件契约](components.md)落地。

## 视觉设计与阅读尺度

- 每款模板选择一个主要视觉重心，例如罗马卷序、网格大序号、票根分栏、印章或终端标题。其余组件配合这个重心，避免章节、引用、说明与摘要都使用同样厚重的外框。
- 普通中文正文以 16–17px、约两倍行高为起点，正文使用清楚的中性色，强调色集中在序号、局部重点与标签。文学风格可用宋体正文与楷书标题，长段落避免全部使用手写感字体。
- 标题、正文、引用和辅助标签拉开主次。小标题不重复整块章节装饰；资料区优先使用留白、浅色底或局部细线，独立案例和摘要再考虑完整边界。
- 完成核对的底色、边线和标签使用本模板色板，不继承通用绿色；默认翡翠序章保持既有样式。有意设计的双色、警告框的琥珀提示色、代码语法高亮和苹果窗口圆点保留各自用途。
- 手机预览避免纸张与正文的内边距叠加，尤其是暗色模板。长标题允许自然换行，章节编号保持完整；较长罗马序号、中文数字及三位数在侧栏内缩小，不拆行、不覆盖标题。
- 组件全览用于兼容性核对，同文短篇用于判断阅读节奏。自动检查不能代替视觉判断；实际查看手机字号、行长、章节留白、相邻组件和深浅色对比。

## 增加或调整模板

新增 JSON 文件，保持下列字段：

- `id` 为唯一的小写英文与连字符标识，`name` 为中文显示名，`order` 为显示顺序。
- 在 `assets/gallery-samples.json` 中用同一 ID 添加 `title`、`lead`、`heading`、`body`、`extra` 与 `continuation`，让外部卡片展示符合模板主题的文章；`continuation` 从新的二级章节标题开始，`extra` 与后续章节使用已有 Markdown 与组件语法，不改动完整组件示例。
- 在 `assets/gallery-filters.json` 的 `templates` 中用同一 ID 添加 `color` 和 `style` 分类数组，值取自相应筛选选项；按实际主色与视觉风格归类，不能只根据模板名称判断。
- `aliases` 提供名称别名；`category` 与 `description` 说明风格及适用内容。
- `colors` 提供 `accent`、`strong`、`text`、`heading`、`muted`、`surface`、`line`、`canvas`。
- `typography` 提供 `bodyFont`、`headingFont`、`size`、`lineHeight`、`spacing`。字体使用本机字体栈，不依赖在线字体。
- `textures.grain` 为兼容保留的可选内嵌 PNG 数据地址；复制到公众号时不保证背景图片被导入。现有颗粒和网格纹理优先使用行内渐变并设置纯色底，不把外部素材路径写进可复制的样式。
- `layout.heading` 使用上表的结构标识，决定章节结构及整套信息组件样式；在共享引擎中定义新的结构与配套角色，不将新增风格只做成配色覆盖。
- `layout.number`：`roman` 为罗马数字，`chinese` 为中文卷序，`han` 为中文数字，`bracket` 为方括号数字，`chapter` 为“第 01 节”，`plain` 为不补零的数字，其余为两位数字。`radius` 是通用卡片圆角，旧字段 `rule` 仅为兼容保留。
- `styles` 只存必要的角色样式覆盖，完整共享角色在 `assets/theme-engine.mjs` 的 `buildStyles` 中定义。可选 `paper` 只影响预览纸张；正文的暗色、暖纸、方格或颗粒背景仍须在 `article` 中设置实际行内背景，不能仅修改网页背景。

`buildStyles` 与 `buildSectionHeading` 分别生成角色样式和章节结构，静态渲染及浏览器切换共用两者。新增布局同步修改这两部分，使用真实节点和行内样式，不依赖伪元素或正文脚本。切换模板时先更新现有角色，再重建章节，保留章节函数对长序号的局部字号调整。序号与标题要协调，长标题可换行而序号保持完整，代码保留苹果圆点结构、原始文字及行内高亮。

改动后运行项目根目录 `dev/` 中的本地工具做回归检查：`render-article.test.mjs` 回归渲染结果，`check-browser.mjs` 做全组件浏览器检查，`capture-template-previews.mjs` 更新模板截图；这些工具不随 Skill 安装，重新生成的组件与风格全览也一并复查。实际查看桌面、390px 与 320px 预览，核对引用、警告、卡片、表格、代码和复制。风格差异应在移除颜色后仍有可辨认的布局与组件形态，不能靠数量掩盖重复样式。
